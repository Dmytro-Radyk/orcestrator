# Gemini та інші моделі Antigravity

Оркестратор підтримує встановлений Antigravity CLI `agy` з перевіреним контрактом `1.5.9–1.5.x`. Це окремий backend `antigravity`, а назва моделі — точний slug із живого каталогу. CLI шукається у PATH та `~/.gemini/bin`; інший native executable можна задати через `ORCHESTRATOR_ANTIGRAVITY_COMMAND` у приватному `.env.local`.

## Вхід, квота й тариф

Discovery виконує лише `--version`, `models` і штатний звіт `--print /usage`, без модельного запиту. У каталозі зберігаються тільки IDs, назви, джерело, версія, час перевірки та числові квоти. Email, токени, баланс кредитів, платіжні дані й довільні поля CLI не копіюються.

Для підписного маршруту потрібні відомі п'ятигодинне та тижневе вікна відповідної групи. Для Argon також враховується окрема тижнева квота. Нульовий залишок, невідомий формат, відсутнє вікно або застарілі метадані блокують запуск. Точний план Pro/Ultra не виводиться з назви моделі й не вигадується: звіт CLI його не розкриває. Weekly-only доступ поки залишається непідтвердженим, а не помилково позначається підпискою.

Кожний модельний виклик отримує CLI override `useG1Credits: false`, `modelProvider: ""` та точний `--model`. За контрактом CLI це обмежує роботу включеною квотою без переходу на AI credits. API/ADC-вхід та endpoint overrides не передаються дочірньому процесу. Доступ повторно перевіряється перед кожним викликом; відмова провайдера не призводить до прихованої заміни моделі.

## Окрема конфігурація

CLI працює з окремими HOME/USERPROFILE у приватній `.orchestrator/antigravity/profile`. Штатний вхід використовує native OS keyring; оркестратор не читає й не копіює credential-файли. Глобальні plugins, hooks, MCP та налаштування основного Antigravity не переносяться. Якщо на іншому комп'ютері native keyring не надає вхід окремому профілю, discovery відмовляє; потрібен штатний Google-вхід, а не API-ключ.

Перед запуском перевіряються executable customizations окремого профілю та батьків його робочої папки. Наявні hooks, MCP чи plugins блокують цей runtime. Глобальна конфігурація користувача не змінюється. Читання/запис файлів, shell, браузер і MCP у моделі заборонені через явні CLI deny rules. Slash/skill expansion вимкнено. У потоці перевіряється точна модель, завершений `SUCCESS` і відсутність tool steps; stderr не потрапляє в UI.

## Планування та виконання

Дозволені маршрути доступні для ідеї, плану, AI-підбору команди, виконання, перевірки та автоматичного відновлення. Сам оркестратор не приписує моделям вигадані рейтинги якості. Користувач може вибрати конкретного AI-керівника у формі підбору.

Для файлів використовується керований file worker: модель отримує обмежений контекст і повертає JSON-зміни. Сервер перевіряє шляхи та baseHash, застосовує зміни в ізольованій worktree й незалежно виконує Node-перевірки у sandbox. `.gemini`, `.env`, `.codex` та інші секрети виключені з файлового контексту. Самі CLI-інструменти моделі не надаються, тому маршрут має `tools: false` і `managedFileChanges: true`.

Токени зі штатного `result.usage` передаються у звіт запуску. Включений доступ підписки не позначається як нульова токенна вартість API.

## Перевірка 16.11.2026

Пройшли 117 тестів оркестратора. Живий metadata-запит повернув 18 маршрутів Antigravity. Окремий короткий Gemini Flash запит підтвердив виконання через ізольовану конфігурацію з вимкненими AI credits.

У повному живому циклі `gemini-4-hydrogen-high` обрав `gemini-3.8-flash-medium` між двома дозволеними Flash-кандидатами для простої задачі. Виконавець створив функцію `isNonEmptyString` і тести в окремій worktree; незалежний sandbox підтвердив 4/4 тестів, після чого файли інтегрувалися в прийняту папку. Керівник і виконавець повернули штатний usage. Приватні журнали, квоти акаунта та згенерований тестовий проєкт залишаються тільки в ігнорованій `.orchestrator/`.
