# Цільовий продукт

Детальний дизайн: [архітектура та структура](architecture/README.md). Вона уточнює цю функціональну карту. Актуальна послідовність реалізації та критерії готовності описані в [плані реалізації](architecture/DELIVERY.md).

Робочий простір для створення й редагування проєктів командами AI-агентів. Користувач задає мету, контекст, критерії приймання, бюджет і доступні інструменти; оркестратор пропонує склад команди, розбиває роботу, виконує її та показує перевірений результат.

## Основні сутності

`Project → Revision → Run → Task → Agent invocation → Artifacts / Usage / Events`

Задачі мають залежності; делегування утворює окреме дерево `parentId`. Агент — профіль можливостей, а invocation — конкретний запуск цього профілю. Один профіль може брати участь у багатьох задачах. Збережений знімок ревізії забезпечує пояснюваність історії.

## Функціональна карта

| Напрям | У версії 0.1 | Розширення |
| --- | --- | --- |
| Проєкти | JSON, локальний API, ревізії | Майстер створення, імпорт репозиторію, шаблони, архівування |
| Реєстр агентів | Ролі, навички, інструкції, API/CLI | Глобальна бібліотека, перевірка доступності, версії промптів, профілі ресурсів |
| Підбір команди | Ручний або збіг навичок | Оцінка якості на власних задачах, ціни, latency, контексту, доступності |
| Планування | Заданий граф задач; делегування агентом | Автоплан з мети, редактор графа, зміна плану під час запуску |
| Командні режими | Parallel, pipeline, reviewer | Дебати, голосування, арбітр, ensemble, перехресна перевірка |
| Субагенти | Дерево, обмеження, скасування, підсумок | Окремі права дітей, передача задач, листування агентів, зміна виконавця |
| Виконання | Пауза, скасування, retries, таймаути | Черги пріоритетів, rate limits, circuit breakers, fallback, checkpoint/resume |
| Репозиторії | CLI у вказаному каталозі, блокування конфліктів | Worktree на виконавця, diff, тести, merge, rollback, створення PR |
| Контекст | Мета, залежності, результати дітей | Файли, документи, пошук, RAG, контроль обсягу, спільна пам'ять |
| Інструменти | CLI-інструменти провайдера | MCP, реєстр інструментів, дозволи на окремі виклики, аудит |
| Витрати | Ліміт запусків, usage як повернув провайдер | Грошові ліміти, резервування бюджету, тарифи, бюджети команди/задачі |
| Спостереження | Події та результати у JSON/API | Потокові логи, timeline, дерево викликів, метрики, експорт |
| Інтерфейс | CLI та HTTP API | Веб/desktop-панель, канбан, граф, чат з керівником, редактор команди |
| Надійність | Валідація, атомарний файл, interrupted | SQLite/Postgres, журнал виконання, durable workers, crash recovery |
| Доступ | Локальний токен, native CLI sandbox | RBAC, секрет-сховище, контейнери, квоти, багатокористувацький режим |

## Послідовність реалізації

Спочатку — доменна модель, контракти, транзакційний стан і виконавець. Далі — керування командами та субагентами, панель користувача, ізольоване редагування й інтеграція результатів. Розширені інструменти, пам'ять, оцінювання моделей та командний deployment спираються на цей фундамент. Детальні етапи й перевірки визначені в архітектурному плані вище.

Поточне ядро навмисно не називає один бренд «найкращим» для всіх задач. Якість маршрутизації надалі слід оцінювати на наборах задач користувача, з окремими метриками результату, часу й вартості.
