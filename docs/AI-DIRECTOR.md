# OpenCode та AI-керівник: серверний контракт

## Поточна реалізація

OpenCode 2.3.0 встановлено локально у приватному `.orchestrator/tools/opencode-2.3.0/` з офіційного npm-пакета `@opencode/cli-windows-x64@2.3.0`. Install-скрипти не запускались; глобальний PATH не змінювався. Інші встановлення можна підключити через `ORCHESTRATOR_OPENCODE_COMMAND` — абсолютний шлях до native CLI. Потрібна підтримувана версія V2, починаючи з 2.2.6. CLI V1 не використовує цей адаптер.

Адаптер запускає приватний `--standalone` runtime з окремими data/config/cache/state у `.orchestrator/opencode/`. Ключі та OpenCode overrides із середовища не успадковуються; конфігурація проєкту, Claude skills, зовнішні MCP, інструменти та інші провайдери заборонені. Host credentials не копіюються. `auth list --format json` повинен підтвердити порожній список облікових записів; інакше маршрут блокується без logout або зміни облікових записів.

`model.list` дає точні IDs, enabled/status, можливості, ліміти контексту та тарифи. Дозволяються тільки anonymous `opencode`-моделі з нульовими input/output/cache read/cache write у **всіх** цінових рівнях. Назва `free`, нульовий input або наявність підписки не є достатньою підставою. Запит прив'язаний до exact `provider/model`; платного fallback немає. Вичерпання безкоштовної квоти завершує запит помилкою.

На 15.11.2026 живий каталог повернув 12 таких моделей. Це не обіцянка незмінного списку або невичерпної квоти. У метаданих немає залишку anonymous-квоти; готовність означає доступність у каталозі, а не гарантований успіх inference. Перед кожним викликом discovery виконується повторно. Використовується `run --format json`, prompt через stdin, без shell. Результат приймається лише за наявності тексту та повного `step_finish` із нульовою вартістю; помилки, обрізані відповіді та виклики інструментів відхиляються.

## Автоматичний керівник

Планувальник UI тепер обирається з підтвердженого каталогу. `GET /api/planning/status` повертає фактичні `model`, `provider`, `routeId`, `configured` та причину недоступності. Концепція й план використовують цей маршрут; provenance містить фактичний model ID, route ID та usage. Формат відповіді існуючого майстра збережений.

За замовчуванням вибір автоматичний серед допустимих кандидатів із JSON-виводом. Це вибір доступного кандидата, а не виміряний рейтинг найсильнішої моделі. У поточному каталозі обрано `opencode:opencode/big-pickle`. Для закріплення задайте:

```dotenv
ORCHESTRATOR_DIRECTOR_ROUTE=opencode:opencode/big-pickle
```

Закріплений недоступний маршрут блокує планування, без мовчазної заміни. Старі `ORCHESTRATOR_PLANNER_MODEL/PROVIDER/REASONING` більше не визначають автоматичного керівника локальної панелі; `plannerConfig()` залишається сумісним бібліотечним інтерфейсом. Параметри Codex executable використовуються discovery, а `ORCHESTRATOR_EXECUTOR_*` — наявним виконавцем. Тип наявної підписки Codex визначається штатним metadata API; його запуск залишається забороненим через непідтверджену межу додаткових кредитів.

## Новий API призначення точних моделей

`POST /api/routing` приймає **серверно збережений** проєкт:

```json
{
  "projectId": "project-id",
  "revision": 1,
  "priority": "balanced",
  "maxAgentsPerTask": 1,
  "requirements": {
    "concept-task": { "workspaceWrite": false, "tools": false, "contextTokens": 8000 }
  }
}
```

Використовуються ті самі same-origin перевірки та `X-Execution-Token`, що й для виконання; Content-Type — JSON. `managerRouteId` є необов'язковим закріпленням керівника для цього рішення. Пріоритети: `quality`, `balanced`, `economy`. `maxAgentsPerTask` має значення 1 за замовчуванням; можна явно дозволити від 1 до 6 моделей на задачу. Це обмежує зайве розмноження виконавців і витрати токенів. Для задач без явних requirements сервер вимагає `workspaceWrite: true`. Тому поточні текстові OpenCode-маршрути не будуть призначені на запис файлів.

Сервер передає керівнику TaskBrief, компактний каталог і окремий список допустимих `candidateRouteIds` кожної задачі. Відповідь:

```json
{
  "id": "proposal-id",
  "projectId": "project-id",
  "revision": 1,
  "planFingerprint": "sha256",
  "assignments": [
    { "taskId": "concept-task", "routeIds": ["opencode:opencode/big-pickle"], "reason": "Обґрунтування та невизначеність" }
  ],
  "routes": [],
  "provenance": { "mode": "ai", "routeId": "opencode:opencode/big-pickle", "model": "opencode/big-pickle", "provider": "opencode", "at": "ISO time", "usage": {} }
}
```

`routes` фактично містить snapshot вибраних маршрутів із model ID, backend, billing, capabilities, джерелом і часом перевірки. У прикладі список скорочено. Перевіряються повне покриття задач, дублікати, від 1 до 6 маршрутів на задачу, допустимість для конкретної задачі та наявність пояснення. Після відповіді тарифи й доступ перевіряються знову. Зміна плану чи ревізії під час inference відхиляє рішення; повторний паралельний підбір того самого проєкту блокується.

`GET /api/routing?projectId=...` повертає `{ proposal, stale }`. Пропозиція зберігається окремо у `.orchestrator/ui/state.json`; вона не змінює план і не запускає виконавців. Поки підтримуються плани до 30 задач. Старі UI agentIds і точні routeIds є різними ідентифікаторами.

## Що врахувати при підключенні UI

- Використовувати `routeIds` нового API, щоб показувати фактичні моделі, причини вибору та невизначеність; статичний профіль ще не є підтвердженим маршрутом.
- Для anonymous OpenCode використовувати `authType: anonymous`, `requiresAuth: false`: це доступ без входу, а не помилка авторизації. Сервер повертає `authenticated: false`, бо акаунта немає.
- Поточний майстер `team` продовжує підтримувати старий контракт профілів. Новий API точних призначень ще потрібно підключити до його екрана й подальших bindings виконання. UI-файли на цьому етапі не змінювались.
- OpenCode зараз виконує лише текстові задачі без інструментів, файлів і субагентів. Повний file-editing worker, ізоляція його workspace, прийняття/застосування пропозиції та відображення живих route IDs у 3D-сцені — наступний етап.

## Перевірка

62 автоматичні тести пройшли: нульові тарифи всіх рівнів, відсутність ключів у дочірньому процесі, валідація JSONL, відхилення неповних результатів, недоступних можливостей, вигаданих маршрутів, змін тарифу, застарілих планів, надмірної кількості виконавців та паралельних рішень. Окремо живий короткий запит повернув `{"ok":true}` із `cost: 0`; живе AI-опрацювання концепції та пропозиція маршрутів також завершились із нульовою вартістю.
