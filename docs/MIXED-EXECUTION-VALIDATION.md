# Перевірка Codex-керівника та безкоштовних виконавців

15.11.2026 через production HTTP API перевірено змішаний цикл: керівник Codex за підтвердженою підпискою → безкоштовні файлові виконавці → окрема модель перевірки → незалежні sandbox-тести.

## Живий сценарій

GPT-6.1 Sol отримав план утиліти `chunk(items, size)` і призначив DeepSeek V4.1 Flash Free на реалізацію та документацію. Дві задачі виконувалися паралельно в окремих worktree. Сервер застосував зміни, запустив 13 Node-тестів та інтегрував код і README.

Перша окрема модель перевірки, GLM 5.3 Flash Free, спробувала викликати заборонений інструмент. Відповідь відхилено; історичний запуск залишився невдалим, а успішно прийняті файли збереглися. У новій ревізії плану повторено лише read-only перевірку. GPT-6.1 Sol обрав Big Pickle після явного виключення невдалого маршруту та маршруту реалізації. Перевірка завершилася успішно, повторно виконавши всі 13 тестів. SHA-256 трьох прийнятих файлів після перевірки не змінилися.

Додатково створено окремий worktree для контрольних тестів, яких не писала модель-виконавець. У network-disabled read-only sandbox пройшли три групи перевірок: порядок і межі chunk, валідація аргументів, збереження object identity та відсутність зміни вхідного масиву. Контрольний worktree не інтегрувався в проєкт.

Усі успішні OpenCode-виклики повернули `cost: 0`. Codex-керівник використав квоту підтвердженої підписки; його usage не позначається безкоштовним. Перша невдала спроба перевірки не має повного звіту токенів. Події, usage, знімки планів і результати збережені лише у приватному `.orchestrator/`.

Це перевірене відновлення через новий AI-підбір і запуск задачі в новій ревізії, а не автоматичне перенесення активної задачі між моделями. Якість довільних проєктів цей окремий сценарій не гарантує.

## Контракт підбору

Для керівника й виконавців задаються незалежні умови:

```json
{
  "projectId": "saved-project-id",
  "revision": 2,
  "managerRouteId": "codex:gpt-6.1-sol",
  "maxAgentsPerTask": 1,
  "requirements": {
    "review": {
      "workspaceWrite": false,
      "tools": false,
      "billing": "free_tier",
      "excludeRouteIds": ["opencode:opencode/failed-model"]
    }
  }
}
```

`billing` підтримує `free_tier` або `subscription_included`. Якщо поле пропущене, діє загальна політика доступу. `excludeRouteIds` виключає до 100 унікальних маршрутів для конкретної задачі. Обидві умови перевіряються до inference керівника, після його відповіді та перед запуском збереженої пропозиції. Жодне з цих полів не дозволяє metered-тарифи або обхід каталогу.

## Перевірка збоїв

Автоматичні інтеграційні тести без реальних AI-запитів перевіряють досягнення порога квоти, появу додаткових кредитів і недоступність metadata під час виконання. У кожному випадку:

- активний Codex-виклик отримує abort;
- задача має `blocked` і `blockedReason`, без повторних спроб навіть із `retries: 3`;
- залежна задача блокується, незалежна безкоштовна завершується;
- прийняті файли залишаються незмінними, часткові зміни лишаються у candidate worktree;
- провайдер не може повідомити успіх після відкликання доступу, навіть якщо проігнорував abort.

Спроба інструмента у текстовому OpenCode-маршруті також дає `blocked`, `blockedReason: tools_not_supported` і `blockedRouteId`, без сліпого повтору. Після зміни тарифу пропозиція `free_tier` не може запустити виконавця як підписку, навіть якщо такий маршрут загалом дозволений.
